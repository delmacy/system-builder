# Station shared visual foundation

Source-owned public React API; imports go through `@system-builder/ui-core`. ADR-0017 uses shadcn open-code visual/design grammar (semantic themes, data-slot anatomy, restrained surfaces and keyboard/focus states). New native primitives are original SB implementations, not copied upstream files. No new headless provider dependency. React/Next/Tailwind versions remain pinned by the existing package lock.

Import `foundation.css` once at the Station host. Themes and comfortable/compact density inherit through the existing presentation boundary. Composition and WindowGeometry remain separate.

Construction B exports Label, Textarea, Checkbox, RadioGroup, Switch, Slider, NumberField, FieldDescription, FieldMessage, Alert, Progress, Skeleton and Card anatomy. Native input state uses normal checked/defaultChecked/value/defaultValue/onChange. Give every input an accessible name via Label/htmlFor, wrapping Label or aria-label; invalid controls also need a described message. These are presentation controls, never business validation/authority.

RadioGroup requires nonempty unique option values and a known selected/default value. Each unnamed group gets an independent native name; explicit names deliberately share a radio relationship and must be chosen by the caller. It supports controlled value/onValueChange and uncontrolled defaultValue. Native browser radio keyboard behavior is retained. NumberField emits finite numbers or undefined for empty/invalid numeric input; HTML min/max/step validity remains native. Slider is native range, not a custom multi-thumb contract.

Progress accepts optional value (absent = indeterminate); nonfinite, negative, overflow or nonpositive max rejects explicitly. Skeleton is decorative; the owning loading region supplies aria-busy/live meaning. Alert role defaults to alert for error, status otherwise; owner chooses timing and content. Card anatomy is source-owned and composable without introducing a second registry.

Status: implemented source/Lab controls; general editor insertion/Inspector properties/preview/codec/save-readback require Construction F qualification. Native Select is not Combobox. Avatar deferred pending actual use. Overlay/menu behavior and broad accessibility certification are separate gates. No full upstream parity claim.

## Overlay/navigation provider (Construction C)
Original SB wrappers in overlays.tsx consume @base-ui/react exactly1.9.0, MIT, from https://github.com/mui/base-ui/tree/v1.9.0. The package retains its upstream LICENSE; no copied upstream source. Lockfile records integrity. Provider exports are isolated behind ui-core; swapping providers requires SB API and behavior conformance tests. Provider event-detail types are currently reflected by ComponentProps and must be considered during replacement.
Dialog/AlertDialog, Popover, AccessibleTooltip, DropdownMenu/submenu, ContextMenu, Menubar, Tabs, Accordion/Collapsible and Breadcrumb anatomy are source/Lab-only. AccessibleTooltip is distinct from the legacy Tooltip surface; no existing API removed. OverlayPortalProvider accepts a theme/density-scoped host; the existing Lab supplies its region element, preserving inherited Station CSS inside portals. Outside a host, provider body fallback applies; callers must supply a host for scoped themes. Caller supplies accessible titles/descriptions, real links, commands and initial/final focus overrides where needed. Alert confirmation is never business authorization. Command palette/Combobox candidates remain residual construction; general composition insertion remainsF.

Keyboard contracts: TabsList uses manual activation by default (arrow focus, Enter/Space selects); activateOnFocus opts into automatic selection. Disabled menu items remain discoverable by arrow focus but cannot invoke their command or dismiss the menu. Tooltip opens on actual keyboard focus-visible/hover, not every programmatic focus following pointer input. These semantics are tested rather than overridden with bespoke handlers. Tab rows wrap at narrow widths.

AccessibleTooltip owns a stable per-root description ID; its content enforces role=tooltip and that ID. Trigger aria-describedby merges caller-owned help IDs with the shared tooltip reference. Caller overrides cannot remove the tooltip role/association. Closed tooltip content is unmounted by the provider; only mounted descriptions are resolved by assistive technology. This semantic layer is SB-owned because Base UI1.9.0 supplies behavior without automatic role/description association.

## Workstation presentation compounds (Construction D, in progress)
Toolbar, ToolbarGroup, ToolbarButton, ToolbarSeparator, PaneHeader, StatusBar, PropertySection and PropertyField are source-owned typed exports. Toolbar, ToolbarGroup and ToolbarButton require accessible labels; only toggles supply `pressed`, regular commands omit it. Native button behavior, owner-supplied callbacks and focus rings are retained. Toolbar does not yet assert composite roving-tabindex keyboard behavior; this is a D qualification gate, not an accomplished feature. Avoid claiming complete WAI-ARIA toolbar pattern from markup alone.

PaneHeader, PropertySection/PropertyField and StatusBar render structural workstation patterns. PropertyField groups a label with a caller-owned control; the caller still must supply the input's own accessible name. StatusBar is an application-local status region, not an automatic live announcement guarantee. No new editor schema/Inspector persistence or business authority is introduced.

D remains in draft pending semantic icon consumption, live Station Lab integration, accessible keyboard/browser tests and full exact-head CI. No components are editor-ready until F registration plus successful insert/edit/save/reopen proof.

## Collection foundation (Construction E, qualification pending)
DataTable is a source-owned semantic local table with stable row/column keys, header sorting intents and per-row command selection. Its `onSelect(key)` deliberately excludes the native HTML table selection event; sort and selection data state remain caller-controlled. Explicit ready/loading/error/empty states and accessible column sort information are provided. Sorting order, filtering, pagination and data access remain consumer-owned. The Station collection Lab demonstrates deterministic sorting, filtering, bounded two-item paging and keyboard-accessible row selection. This is not a virtualized DataGrid and does not claim large-list performance. Existing Tree and station-interaction selection remain canonical. Browser/CI proof and editor insertion are separate pending gates; no Editor-ready claim before Construction F.

## Button presentation modes (TASK761)
PresentationButton owns text/icon-text/icon presentation, requiring a nonblank accessible label and a shared semantic IconToken for icon modes. Compact labels use qualified AccessibleTooltip on hover/focus with Escape dismissal; optional caller-controlled expanded reveals the label and supplies aria-expanded. Caller owns all commands/state. No icon pack or codec fields added. Source/Lab-only for composition: portable icon reference/mode persistence requires coordinated ICON migration and registry/Inspector/legacy recovery proof.
