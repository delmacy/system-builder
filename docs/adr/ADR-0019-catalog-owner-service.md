# ADR-0019 — Catalog owner service for Business and Software Studio
Date:2026-10-12. Status: PROPOSED — owner decision required; no construction authority.
## Context
STUDIOS-WP02 needs real server-owned twofamily registry/query/reopen/reuse. Current Catalog public software registry/PG and Business promotion/process-admission foundations do not establish authenticated Station-facing operations, trustedupstream resolution, atomic immutable registration and durable result recovery. Generic Gateway/protocol already exists; actual local owner is Design only.
## Proposed decision
1. SB05 owns a bounded versioned Catalog service with distinct Business and Software entry contracts and register/list/exact/result operations.
2. Reuse current software record semantics/resolution and existing canonical Business promotion/process admission; Business eligibility must use actual trusted upstream evidence, not UI assertion.
3. Use a replaceable Catalog-owned transactional repository with additive PostgreSQL reference tables/immutable identity and stable command result ledger. Existing SoftwareCatalogRegistry/provider consumer compatibility stays intact; its queued cache/upsert cannot itself qualify immutable owner writes.
4. Bind public Catalog operations into existing StationGateway/StationCorePort and protocol1.0 through a concrete scoped authenticated adapter/explicit localoperator profile. Modular boundary does not require a new product app/process/container; exact hosting selected in prerequisitePlanning.
5. Server enforces action/resource/type/scope/currentactor/revision/session/context and semantic eligibility. Design credential/grant is not Catalog permission.
6. Build/prove Catalog-owned prerequisite separately before Station client/UI Construction. Every actual Business source resolver must be ready; unresolved ingress/approval owner is an explicit dependency rather than invented success.
## Alternatives and consequences
Client-only/localStorage registry fails real owner/durable/auth objectives. Wrapping legacy provider without atomicresultcommit permits cache-only ACK/upsert collision. Sharing Designcandidateowner conflates authority. Replacing all existingCatalog consumers would create unnecessary migration; preservepubliccompatibility.
Additional owned Planning/A/B/Review/Closure effort depends on actualupstreamreadiness, not automatically absorbed into Station WP02 or promised elapsed time. Catalog newpublicsurface is L3 and adapter/authority decision reviewed as L4; accept before code. No productionIAM, universalcatalog, broadpublish/deprecate/withdraw lifecycle or businessruleinvented.
## Acceptance and exit
Explicit owner acceptance/revision of thisADR; exact owned Planning/schema/paths/readiness/limits. Actual publicowner→PG/Gateway/auth/context→Station proof plus duplicate/incompatible/denied/stale/unknown/restart/result/reuse and predecessorAssembly/knowledgeproof. No futureConstruction committed by proposal.
