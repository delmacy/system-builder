## Purpose

Close the R6 research handoff question by converting the candidate C8 grammar into representative manual journeys, explicit inherited proofs, smallest delta proofs, and exit gaps. Absence of evidence is `unproven-gap`, never PASS. Human acceptance remains separate from machine conformance.

Candidate C8 grammar:

`tool identity + participant-role contract + active-context routing + command/capability projections + presentation/restoration policy`

A Tool coordinates presentation and invocation surfaces. It does not own Core/business truth, strengthen command results, or infer authority from focus, visibility, selection, enabled state, transport acceptance, or restored snapshots.

## Benchmark delta reconciliation

Independent workstation families converge on stable command/action identity separated from UI projection, context-conditioned applicability, stable semantic participant roles despite placement/focus changes, and task/workspace grouping without domain-object authority. They diverge in contribution metadata, docking, plugin APIs, serialization and context mechanisms. Station therefore classifies the shared grammar as `own/adapt`, context-conditioned projection and stable participant identity as `adopt-pattern`, and provider-specific workbench/plugin/serialization mechanisms as `defer`.

No benchmark feature creates Station scope merely by existing elsewhere.

## Proof inheritance boundary

C8 may inherit lower-level machine evidence only where preconditions are unchanged: primitive keyboard/focus/activation; grouping/slot compatibility; command identity/target/currentness; `availability != authority`; result/evidence non-strengthening (`accepted != effective`, partial, unknown, stale); region identity != placement; presentation-only hide/move/maximize; and C7 definition/role/variant semantics where actually proven.

Carried R3–R5 gaps remain gaps, especially semantic reparent/order/cycle/reachability, contract/schema→Inspector, canonical graph→Layers, source/YAML round-trip and multi-projection synchronization.

## Promotion / dedup exit rule

Promote C7 → C8 only if the orchestration invariant is reusable across materially different domains, survives admitted participant/layout changes, is expressed through declared participant roles and context routing, keeps commands/capabilities separately owned, and introduces a proof delta not discharged below C8.

Domain nouns, labels, icons, command bindings, default pane placement, visibility defaults, spans, data source choice and compatible participant substitutions remain configuration. Therefore `ApprovalTool`, `TicketTool`, `CrudTool`, `DashboardTool` and `DeploymentTool` are rejected as default grammar pieces while one C8 contract expresses them.
