## Omission details

### O1 — Contextual interaction ownership

R2 explicitly rejects a universal `focus == selection == active == expansion` abstraction and requires contextual keyboard arbitration. R3 carries accessibility/contextual-keyboard proof debt. D03 currently separates identity/placement/presentation/action but does not preserve this orthogonality explicitly.

**Disposition:** `adopt-pattern + own boundary`.
**Required proof:** collection/Tool journeys must show traversal ownership, embedded-control key capture, exit/restoration, and no inference of authority from focus/selection/active state.

### O2 — Result non-strengthening and recovery ownership

R3 proves, in bounded owner contexts, that accepted/acknowledged is not necessarily effective and that partial/unknown/retry/compensation are owner-qualified. R6 and R7 require projections to preserve those distinctions. D12/D17 imply authority boundaries but do not make result non-strengthening a first-class synthesis decision.

**Disposition:** `own/reuse owner contract + adopt-pattern`.
**Required proof:** all admitted projections preserve REJECTED/PARTIAL/UNKNOWN/stale/reconcile-required; retry is owner-eligible and revalidated; editor undo/discard never implies business compensation/rollback.

### O3 — Registry / contribution isolation

R7 executable evidence proves bounded AppManifest identity/shape and rejects authority-shaped fields, but semantic Tool compatibility, contribution isolation and `AppManifest != ComponentRegistry` remain explicit gaps. D15 states the level distinction without the isolation proof.

**Disposition:** `own`.
**Required proof:** manifest resolution cannot register component species, mutate ComponentRegistry, bypass command/capability registries, or create Core/business authority; incompatible contributions fail before activation.
