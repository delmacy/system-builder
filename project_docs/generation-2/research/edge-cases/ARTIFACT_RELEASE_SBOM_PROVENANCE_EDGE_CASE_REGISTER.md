## Evidence anchors

- SLSA Provenance separates output subject from `buildDefinition` and `runDetails`; provenance accuracy/completeness depends on the builder identity and build-platform evidence. https://slsa.dev/spec/v1.0-rc2/provenance
- SLSA Build Requirements explicitly distinguish provenance integrity from completeness and require provenance data to originate from the build platform for stronger claims. https://slsa.dev/spec/v1.2-rc1/build-requirements
- Sigstore bundles contain signature content plus verification material; verification of identity-based signatures requires expected signer identity and issuer, while trust roots and timestamps/transparency evidence matter to verification. https://docs.sigstore.dev/about/bundle/ and https://docs.sigstore.dev/cosign/verifying/verify/
- Sigstore's security model makes trust-root and authenticated identity part of the trust claim and notes that compromise detection depends on monitoring; a valid signature therefore does not by itself prove authorization to release or completeness of provenance/SBOM. https://docs.sigstore.dev/about/security/ and https://docs.sigstore.dev/about/threat-model/

These representatives support portable semantics only; their product-specific formats/mechanisms are not promoted as universal architecture.

## Local material scenarios

### G2-EDGE-ARTIFACT-001 — release subject, SBOM subject and provenance subject do not identify the same immutable bytes
Activation: mutable tag/name, packaging transformation, multi-platform manifest, rebuilt archive or metadata attachment causes subject identities to diverge. Safe behavior: compare immutable subject identities and scope; mismatch is `INCONCLUSIVE/NON_CONFORMING` for admission. Forbidden: tag/version equality proves subject equality. Owners: Artifact/Release + Build + Standards. Evidence: artifact digest/set, SBOM/provenance subject scope, packaging lineage. Recovery: identify exact bytes and supersede/reissue metadata rather than overwrite history. Blast radius: release/runtime fleet. Severity: CRITICAL; confidence: strongly supported; detectability: pre-release/audit; reversibility: bounded before deployment; time-to-harm: immediate; misuse: likely accidental; false-positive risk: medium for explicitly scoped multi-subject attestations. Proof: `ARTIFACT-ADV-PROOF-001`.

### G2-EDGE-ARTIFACT-002 — authentic provenance or SBOM is incomplete/stale but treated as complete
Activation: dependencies/materials/components omitted, generated after build from a partial view, or retained after artifact/material correction. Safe behavior: authenticity, completeness, applicability and currentness are independent qualifications; missing coverage weakens the claim to `PARTIAL/INCONCLUSIVE`. Forbidden: cryptographic verification implies complete dependency/material inventory. Owners: Artifact/Release + Build + Security/Supply-chain. Evidence: generating revision/profile, coverage declaration, material closure, observation time. Recovery: regenerate/augment and preserve correction/supersession lineage. Severity: CRITICAL; blast radius: supply chain/fleet; reversibility: bounded before use; time-to-harm: latent; misuse: plausible. Proof: `ARTIFACT-ADV-PROOF-002`.

### G2-EDGE-ARTIFACT-003 — signer signature remains cryptographically valid after release authority/trust eligibility changes
Activation: Role/Station membership, signing policy, trust root, issuer, key/certificate eligibility or delegated release authority changes after signing or before promotion. Safe behavior: cryptographic validity and release authorization/current eligibility remain distinct; verification uses applicable historical signing-time evidence plus current admission policy. Forbidden: valid signature means signer is currently/was canonically authorized for this release scope. Owners: Enterprise Trust/PKI + Identity/Authorization + Artifact/Release. Evidence: signature timestamp, identity/issuer, trust-root revision, authority revision/scope, release policy. Recovery: re-assess admission, revoke/supersede/fence if concretely ineligible. Severity: CRITICAL; detectability: pre-promotion/audit; blast radius: enterprise/external parties; reversibility: difficult after distribution; time-to-harm: immediate/latent; misuse: plausible adversarial. Proof: `ARTIFACT-ADV-PROOF-003`.

### G2-EDGE-ARTIFACT-004 — concurrent promotion, revocation and supersession create incompatible release truth
Activation: one actor promotes while another revokes/supersedes or metadata/signature correction races with distribution. Safe behavior: transitions use revision/currentness evidence and preserve ordered lineage; ambiguous remote effects remain `UNKNOWN/PARTIAL`. Forbidden: last API response or registry tag silently decides canonical release state. Owners: Artifact/Release + Lifecycle + Authorization + Provider/Binding. Evidence: release revision, transition attempts, authority/currentness, provider observations. Recovery: reconcile all publication/distribution cohorts before retry/closure. Severity: CRITICAL; detectability: runtime/audit; blast radius: fleet; reversibility: provider dependent; misuse: plausible. Proof: `ARTIFACT-ADV-PROOF-004`.

### G2-EDGE-ARTIFACT-005 — remote signing/publication/distribution timeout is blindly retried
Activation: signature, registry push, metadata publication or revocation request times out after possible effect. Safe behavior: preserve `APPLIED/NOT_APPLIED/PARTIAL/UNKNOWN`; `UNKNOWN → reconcile-before-retry` unless idempotency scope/horizon is qualified. Forbidden: timeout equals failure or retry cannot create competing authoritative records. Owners: Artifact/Release + Provider/Binding + Integration + Trust/PKI. Evidence: attempt IDs as realization evidence, subject digest, signature/bundle identity, registry observations, idempotency contract. Recovery: reconcile remote state and adopt/supersede one canonical lineage. Severity: CRITICAL; blast radius: external consumers; reversibility: difficult; time-to-harm: immediate. Proof: `ARTIFACT-ADV-PROOF-005`.

### G2-EDGE-ARTIFACT-006 — retained release is intact but no longer currently eligible
Activation: dependency revoked, trust root/policy changes, runtime support withdrawn, vulnerability/compatibility evidence changes, or release is retained for rollback. Safe behavior: historical integrity/retention != current admission/rollback eligibility; requalify applicable evidence before use. Forbidden: retained digest/signature means safe/current release. Owners: Artifact/Release + Lifecycle + Security/Recovery + affected owners. Evidence: historical release proof plus current trust/support/dependency policy. Recovery: choose eligible target or explicitly accept bounded risk through governance. Severity: CRITICAL; blast radius: runtime fleet; reversibility: bounded pre-activation; time-to-harm: immediate. Proof: `ARTIFACT-ADV-PROOF-006`.

### G2-EDGE-ARTIFACT-007 — very large SBOM/provenance graph exhausts verification and induces unsafe bypass
Activation: huge component/relationship/attestation graph, duplicate aliases, recursive references or many signatures. Safe behavior: bounded verification may return `INCONCLUSIVE/DEGRADED` but cannot silently skip required trust/coverage checks. Forbidden: resource pressure disables verification or treats unvisited graph as safe. Owners: Artifact/Release + Security + Runtime/Operations + FinOps. Evidence: graph size/coverage, verification limits, skipped/failed checks. Recovery: partition/stream/queue verification without strengthening claims. Severity: HIGH–CRITICAL; blast radius: release pipeline; reversibility: easy before admission; misuse: plausible adversarial. Proof: `ARTIFACT-ADV-PROOF-007`.
