## Evidence refresh

Current mature-provider evidence continues to support existing classifications rather than a new universal conflict family. HashiCorp Vault dynamic secrets carry leases with TTL/renewability; a consumer must renew or replace them, revocation invalidates the secret, and the actual renewal result must be inspected rather than assuming the requested increment was granted. AWS Secrets Manager rotation distinguishes `AWSPENDING`, `AWSCURRENT` and `AWSPREVIOUS`; moving a staging label identifies a provider-side version state but does not prove fleet-wide consumer adoption. AWS also documents version accumulation under frequent writes, reinforcing bounded rotation/reload/resource considerations. Provider mechanisms remain evidence, not canonical architecture.

## Duplicate-screen results

1. **Atomic snapshot identity across config/secret references.** Independently valid references resolved at different cuts can form an invalid aggregate. Existing revision-vector and qualification-join patterns plus `G2-EDGE-SECRETS-007` cover this; no new class.
2. **Alias/latest drift during rotation.** Stable reference identity can resolve to a different generation across time/replay. Existing currentness/revision lineage plus `G2-EDGE-SECRETS-008` cover this.
3. **Lease currentness versus long-running authority.** Credential validity and business authority are independent clocks; renewal of one cannot extend the other. Existing currentness and authority-re-evaluation patterns cover the conflict.
4. **Offline/self-hosted revocation visibility.** A disconnected cohort can retain apparently healthy cached material after central revocation. Existing stale-evidence, degraded-authority and residual-cohort patterns cover this.
5. **Provider namespace/type mismatch.** Same-looking names can identify different object types, scopes, tenants or reveal/use semantics. Existing provider semantic qualification, semantic ownership and qualification-join patterns cover this.
6. **Bootstrap/recovery circular dependency.** Obtaining current config/secret/trust can require a runtime whose safe startup itself requires that material. Existing structural-cycle, recovery-qualification and degraded-authority patterns cover this.
7. **Backup/export resurrection.** Restore can reintroduce historically valid but now revoked/withdrawn material. Existing recovery qualification, rollback eligibility, coexistence and residual-cohort patterns cover this.
8. **Reload/rotation storms.** Individually valid rotations can cause restart/reload/provider-request amplification and mixed generations. Existing resource/capacity and convergence patterns cover this; pressure cannot justify weakening authority/currentness/redaction.
9. **Presence semantics.** `ABSENT`, `null`, default and delete can be translated differently by config/provider/runtime boundaries. This is a Secrets manifestation of `G2-CONFLICT-PATTERN-PRESENCE-SEMANTICS-001`, not a new reusable pattern.
10. **`PARTIAL/UNKNOWN` distribution.** Provider mutation and consumer adoption can diverge or remain ambiguous. Existing ambiguous-effect, reconcile-before-retry and convergence patterns cover this.
11. **Residual old-provider cohorts.** Cutover can leave old credentials/config authoritative for a subset. Existing provider-coexistence/residual-cohort patterns cover this.
12. **Human procedures.** Two locally valid runbooks can conflict over rotate/revoke/restart/rollback ordering. Existing human-procedure, temporal and authority-owner classifications provide owner/detection/remediation routes.
13. **AI/low-code aggregate authority.** Individually permitted references can be composed into a cross-tenant or wider-scope configuration. Existing composition-admissibility and authority non-amplification patterns cover this; a signal is not a confirmed conflict.
