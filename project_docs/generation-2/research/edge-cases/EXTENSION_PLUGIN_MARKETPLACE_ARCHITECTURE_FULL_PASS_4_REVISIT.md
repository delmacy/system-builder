## 2. Current external evidence

Evidence was used only to test portability of already-catalogued distinctions.

- VS Code currently documents distinct extension hosts and execution-location selection. Remote extension dependencies may remain declared/activated while an exported API is unavailable across separate extension hosts.   - https://code.visualstudio.com/api/advanced-topics/extension-host
  - https://code.visualstudio.com/api/advanced-topics/remote-extensions

  - https://code.visualstudio.com/api/get-started/extension-anatomy
  - https://code.visualstudio.com/api/references/extension-manifest
- npm v11 documents peer-dependency constraints, optional peers and dependency-tree behavior. Local package validity or successful resolution does not prove N-wise semantic compatibility of the realized plugin closure.
  - https://docs.npmjs.com/cli/v11/configuring-npm/package-json/
- Chrome runtime documentation exposes cross-extension and native messaging surfaces, showing that effective communication/effect reach may exceed the root package's immediately visible edges.
  - https://developer.chrome.com/docs/extensions/mv2/reference/runtime

Portable conclusion remains unchanged: `installed/admitted != currently qualified aggregate authority`; `dependency declared/resolved != jointly qualified semantic surface`; `disabled/uninstalled != proven effect quiescence`; and trust/integrity evidence is not authorization.

### 3.7 Contradictory human extension-management procedures

Candidate: two individually valid operator procedures prescribe incompatible activation, disablement, trust override, rollback or provider-substitution actions for the same extension cohort.

Disposition: no new reusable class. It maps directly to the existing human-procedure/instruction conflict family plus authority/currentness and lifecycle eligibility. Detection candidate: procedure applicability/precedence graph plus current owner/authority evidence. `Signal != ConfirmedConflict` remains required.

### 3.8 Resource amplification

Candidate: individually valid hooks/dependencies recursively trigger, fan out or create high-cardinality registrations/cost.

Disposition: existing structural-cycle, resource-amplification, capacity/currentness and objective-conflict patterns cover the class. Prevention must remain bounded so legitimate high-scale plugins are not globally forbidden.

Disposition: already covered by `G2-XEDGE-EXTENSION-AUTH-TRUST-LIFECYCLE-004/005`, permission-composition, authority non-amplification, provider qualification, semantic ownership and AI/low-code conflict families.
