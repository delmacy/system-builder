## External evidence refresh

Current provider documentation reinforces the existing catalogue:

- Google Cloud Storage documents that changing Object Versioning configuration can take time to propagate and recommends waiting before subsequent delete/replace operations. It also states that noncurrent versions retain their own metadata and can have permissions different from the live version. This reinforces configuration/evidence currentness and metadata/content revision qualification rather than a new pattern.
- Google Cloud Storage documents that restoring a soft-deleted object creates a new object generation and can reset or re-derive metadata/ACL properties depending on the restore path. Restore therefore proves neither canonical rollback nor semantic equivalence without requalification.
- Amazon S3 documents that aborting a multipart upload does not guarantee already in-progress part uploads have quiesced; those parts may still succeed or fail and provider evidence may need reconciliation.
- Azure Blob immutable storage documents legal-hold scopes at version or container level, reinforcing the already-catalogued distinction between provider protection scope and canonical protection subject.
