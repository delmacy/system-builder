## 1. Full-Pass-4 method

This revisit deliberately used techniques materially different from Full Passes 1–3:

1. **qualification-projection subtraction** — progressively remove owner/revision/currentness dimensions from a fully qualified action projection and test whether a generated surface silently strengthens the claim;
2. **generated-view semantic-cut differential** — compare equivalent canonical work rendered through different generated/personalized views and challenge whether hiding, disabling, grouping, localization, accessibility adaptation or compact modes alter mutation semantics;
3. **optimistic-interaction stale-base mutation** — hold an editable projection while canonical facts, policy, provider eligibility or process state advance, then submit with and without explicit base/currentness evidence;
4. **accessibility/localization metamorphic analysis** — vary language, directionality, date/number formatting, assistive-technology exposure and disabled/hidden presentation while requiring the canonical intent/effect to remain invariant;
5. **offline epoch braid** — suspend a Person/Role/Station work surface, advance policy/schema/provider/identity/process revisions, then resume old drafts/actions and test requalification versus replay;
6. **StoredFact/DerivedValue projection swap** — substitute derived/calculated/current projections for stored historical facts and vice versa to detect accidental promotion of presentation values into canonical truth;
7. **residual-client coexistence analysis** — operate old and new surface revisions concurrently against one canonical subject and challenge compatibility direction, presence/default translation and owner qualification;
8. **resource/cardinality truncation mutation** — increase generated cards/actions/evidence/conditional branches until a surface must paginate, truncate or degrade, then test whether mandatory semantics disappear;
9. **AI/low-code dimension-erasure analysis** — ask an AI/generated builder to simplify or optimize a valid surface and test whether authority, owner, revision, unit, evidence-currentness or mandatory-presence dimensions are erased while syntax remains valid.

## 2. Evidence refresh

Portable evidence only; none of these sources prescribes System Builder target architecture.

1. WHATWG HTML Standard, form-control infrastructure: a disabled control is a presentation/interaction state with distinct form-submission behavior, and its value can still be modified programmatically. This reinforces `visible/disabled/hidden != authorization` and the need to preserve canonical intent across generated views: https://html.spec.whatwg.org/dev/form-control-infrastructure.html
2. WHATWG HTML Standard, form elements: disabled controls can be prevented from contributing values to form submission, illustrating that a rendered value can diverge from the transmitted mutation payload if presence semantics are not explicit: https://html.spec.whatwg.org/multipage/form-elements.html
3. OWASP Authorization Cheat Sheet: deny by default and validate permissions on every request; UI availability is not an authorization proof: https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html
4. OpenFGA immutable authorization models: authorization models are immutable revisions and production callers are strongly encouraged to pin a specific model ID rather than silently follow the latest model: https://openfga.dev/docs/getting-started/immutable-models
5. OpenFGA contextual tuples: request-scoped context is ephemeral; token-derived claims can remain usable until token expiry even after underlying membership changes. This is direct evidence that a previously valid surface context can become stale: https://openfga.dev/docs/interacting/contextual-tuples
6. OpenFGA organization-context authorization: two simultaneous browser/session contexts can legitimately require different authorization context for the same subject, reinforcing that surface/session context must not be collapsed into one global actor state: https://openfga.dev/docs/modeling/organization-context-authorization
7. W3C internationalization guidance documents that date/number presentation varies by locale and can be ambiguous to humans even when canonical machine representation is stable; generated/localized surfaces therefore must not let presentation conversion change canonical meaning: https://www.w3.org/International/wiki/Locale-based_forms

### 3.1 Authority / qualification projection

Candidate: a generated work surface retains an action but drops one or more qualification dimensions — Station/tenant scope, semantic owner, policy/model revision, provider binding revision or evidence horizon — and presents the action as simply “available”.

Disposition: already covered by `G2-EDGE-AGWS-001`, multitenant-scope, qualified-claim/currentness, permission-composition, presentation-authority and provider-qualification families. The surface projection is evidence only and cannot strengthen authority. No new edge or ConflictPattern survives.

### 3.2 Generated-view presence and disabled/hidden semantics

Candidate: one renderer shows a mandatory or pre-populated field as disabled/read-only/hidden while another renderer omits it from the mutation payload, causing `displayed value A` to become `ABSENT/default/delete B` downstream.

Disposition: materially represented by `G2-CONFLICT-PATTERN-PRESENCE-SEMANTICS-001`, `G2-EDGE-UI-011`, `G2-EDGE-INTEGRATION-008`, AGWS mandatory-component handling and owner-qualified mutation semantics. WHATWG evidence deepens detectability but does not justify a new class.

### 3.3 Accessibility/localization differential

Candidate: accessibility adaptation or locale formatting changes the human-readable order/format of date, number, currency, directionality, labels or grouped controls such that the operator may understand a different value/action than the canonical payload.

Disposition: already covered by presentation/semantic-ownership, input-normalization, unit/currency/locale ambiguity, presence semantics and human-instruction conflict families. The portable invariant is that accessible/localized presentation may vary while canonical intent/effect remains owner-qualified. No distinct reusable family survives.

### 3.4 Stale optimistic interactions

Candidate: a surface edits a canonical subject from base revision `R1`; process/data/policy/provider truth advances to `R2`; the stale client submits a still-valid-looking action or draft.

Disposition: already covered by AGWS stale-currentness, UI optimistic concurrency, revision-vector/currentness, lost-update, historical-reactivation and compatibility-direction families. No new material class.

### 3.5 Long-lived/offline work across revisions

Candidate: offline Person/Role/Station work resumes after authority, schema, workflow, provider or policy revision changes and attempts replay/promotion using the old effective surface.

Disposition: already covered by `G2-EDGE-AGWS-009`, residual-cohort, replay-eligibility, correction/supersession, currentness and compatibility-direction families. Historical renderability remains distinct from current actuation eligibility.

### 3.6 StoredFact versus DerivedValue projection

Candidate: a derived/current calculation shown on the surface is later submitted or persisted as though it were the producing StoredFact/historical snapshot, or an old stored value is shown as if it were a live derived value.

Disposition: already covered by the canonical `StoredFact != DerivedValue`, formula-evaluation/historical-recomputation, semantic-ownership and projection-semantics families. No new AGWS-specific pattern survives.

### 3.7 Residual-client coexistence and compatibility direction

Candidate: old and new surface revisions both remain legitimate viewers, but only one direction/operation of compatibility is qualified; an old client then writes, resumes or replays under a compatibility claim established only for read/forward operation.

Disposition: directly covered by `G2-CONFLICT-PATTERN-COMPATIBILITY-DIRECTION-001`, residual cohorts, lifecycle coexistence and AGWS historical-reactivation. This is a required future proof surface, not a new ConflictPattern.

### 3.8 Resource/cardinality pressure

Candidate: valid generated cards/actions/evidence exceed display/evaluation bounds and the degraded surface truncates mandatory evidence, controls, owner context or warnings.

Disposition: already covered by `G2-EDGE-AGWS-006`, UI resource-boundedness and fail-closed projection semantics. No new class.

### 3.9 AI / low-code semantic-dimension erasure

Candidate: AI “simplifies” a surface by merging fields/actions or removing labels/context that appear redundant, but the removed dimension carries authority, owner, unit, revision, evidence-currentness or presence semantics.

Disposition: already covered by `G2-EDGE-AGWS-003`, low-code materialization, permission/automation composition, presence semantics and AI non-amplification. Syntactic or UX simplification cannot erase semantic-owner qualifications. No new reusable class survives.
