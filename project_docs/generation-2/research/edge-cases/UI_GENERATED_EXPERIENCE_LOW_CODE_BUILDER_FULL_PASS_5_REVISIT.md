## 1. Revisit purpose and method

This Full Pass 5 revisit carried the prioritized **Typed Semantic Graph + ExecutionEnvelope + Autonomous Builds/Fleet Observability** hypothesis into generated UI and low-code composition without treating the hypothesis as decided architecture.

The revisit rotated techniques from Full Pass 4 and challenged:

1. **projection-strengthening mutation** — hide, aggregate, collapse, filter, zoom or summarize graph nodes/edges and test whether the view is incorrectly interpreted as proof of absence, safety, authorization, convergence or equivalence;
2. **source/projection identity substitution** — exchange `CapabilityDefinition`, `CapabilityUse`, workflow instance, node execution, deployment/runtime identity, client payload and Fleet aggregate while holding presentation labels apparently constant;
3. **context-barrier falsification** — reuse the same generated surface across Enterprise/Workspace/client/Station scopes and test whether cached, inferred or inherited context widens target population or authority;
4. **revision-cut projection braid** — vary graph definition, workflow, schema, policy, formula, provider, build and generated-client revisions independently while the Canvas remains visually plausible;
5. **presence-state round trip** — permute `ABSENT`, `UNSET`, explicit `null`, default, deleted, redacted and `UNKNOWN` through graph metadata, generated controls and serialized mutations;
6. **interaction/effect differential** — compare optimistic UI state, local queue state and user-visible success/failure with `APPLIED / NOT_APPLIED / PARTIAL / UNKNOWN` owner-qualified effect evidence;
7. **accessibility/localization semantic mutation** — preserve canonical operation identity while transforming visual label, accessible name/role/value, locale, formatting and ordering, then invert the test by preserving presentation while changing canonical operation identity;
8. **Fleet-versus-client falsification** — compare global/Fleet aggregate, exported telemetry and concrete client payload to test whether aggregate evidence is treated as authoritative local state or semantically comparable across builds;
9. **graph/cardinality pressure** — stress nested subgraphs, cross-view overlays, lineage expansion, fan-out actions, high-cardinality telemetry overlays and large generated forms;
10. **AI/low-code aggregate-plan review** — compose individually valid nodes/actions into paths that widen authority, hide evidence requirements, cross owner boundaries, create contradictory work or optimize one objective against another.

## 2. Evidence refresh

Current standards support the distinctions used by the research rather than opening a new reusable conflict family:

- JSON Schema continues to define `default`, `readOnly` and `writeOnly` as annotation-oriented semantics. `default` does not populate missing instance data during validation, and `readOnly`/`writeOnly` do not by themselves establish canonical authorization or mutation semantics. Generated forms therefore require an explicit owner-qualified contract rather than treating schema annotations as complete executable truth.
- W3C ACT guidance continues to distinguish programmatic hiding, accessibility-tree exposure and sequential focus behavior. A visual/DOM state can therefore diverge from assistive interaction semantics without either representation being canonical authority evidence.
- PostgreSQL documentation continues to provide recursive-query support suitable for graph-shaped traversal, reinforcing that navigable graph projection does not imply GraphDB as a required persistence technology.

Portable conclusion: a Canvas/Graph Explorer may be a useful projection of a typed semantic model, but projection visibility, omission, aggregation and traversal affordances are not proof of source truth, authorization, runtime convergence, compatibility or business effect.

## 3. Adversarial results and duplicate-screen

### 3.1 Canvas/Graph Explorer projection versus source of truth

The strongest probe deliberately hid or coalesced edges/nodes at different zoom levels (`Enterprise -> Workspace -> Workflow -> Subworkflow -> Capability -> Contract/Provider`) and across Process/Capability/Data/Authority/Provider/Runtime/Risk views. A locally correct projection can still omit a dependency, residual cohort, authority constraint or unresolved effect.

The unsafe interpretation is **projection strengthening**: treating an omitted relation as proof that the relation does not exist, or treating an aggregate visual state as proof of convergence/safety. This reduces to existing qualified-claim, evidence-currentness, semantic-ownership, residual-cohort and false-convergence patterns. No new `G2-CONFLICT-PATTERN-*` survives duplicate-screen.

Research consequence: any future Graph Explorer should be considered a qualified projection with explicit scope/revision/filter/currentness semantics; this is a proof obligation candidate, not an implementation decision.

### 3.2 CapabilityDefinition versus CapabilityUse rendering

Rendering a canonical capability definition as though it were the concrete invocation can erase workflow position, owner scope, bound provider, revision, inputs/outputs, authority and effect context. Conversely, rendering a particular invocation as though it redefines the canonical capability can create false global semantics.

This remains covered by canonical identity versus use/realization identity, semantic ownership, qualification-join and revision-vector families. `CapabilityDefinition != CapabilityUse/Invocation` remains a surviving research distinction, not a new conflict pattern.

### 3.3 Client/workspace context barriers

A generated surface reused across scopes can be locally valid while stale workspace/client/Station context causes a mutation to target a broader or different subject set than the operator believes. The graph can remain structurally valid throughout.

This reduces to existing authority non-amplification, context/currentness, trust namespace, multitenancy and confused-deputy families. Detection candidates remain explicit target/scope qualification and current-authority re-evaluation before consequential mutation.

### 3.4 Stale graph/revision projections

A Canvas may display graph revision N while the workflow/runtime/provider/policy cut has advanced. Editing or triggering from that view can create a valid command against a stale semantic base. This remains revision-vector completeness, stale-base/currentness and compatibility-direction territory.

No universal rule requires every view to be live; the required property is that the evidence/currentness boundary be explicit enough that stale projection is not silently strengthened into current truth.

### 3.5 Hidden / disabled / read-only versus authorization

Presentation state remains independent from canonical authorization. A disabled/hidden control does not prove absence of server-side authority; an enabled control does not prove current authority. JSON Schema annotation semantics and W3C accessibility behavior reinforce that generated presentation and executable authority are different proof objects.

Existing presentation-authority, current-authority re-evaluation and non-amplification patterns remain sufficient.

### 3.6 Presence semantics through generated graph controls

`ABSENT`, `UNSET`, explicit `null`, default, deleted, redacted and `UNKNOWN` can collapse into visually identical states while producing different owner semantics. The same problem occurs when Canvas property panels serialize missing configuration as defaulted configuration.

This maps directly to the existing presence-semantics family and prior UI/UCA findings. No new pattern is created.

### 3.7 Optimistic/offline interaction under ambiguous effects

A generated client may optimistically show failure while a remote mutation is actually `APPLIED`, `PARTIAL` or `UNKNOWN`; offline/residual clients may replay against a changed graph/provider/authority revision. Retrying from the Canvas without reconciliation can duplicate or contradict already-adopted work.

This remains ambiguous-effect/reconcile-before-retry, residual-cohort, compatibility-direction and adoption-aware compensation territory.

### 3.8 Accessibility/localization semantic drift

Visual labels, accessible names, role/value exposure, locale formatting and ordering can diverge while the canonical action remains the same; or the presentation can look unchanged while the action identity changes between revisions. These are projection/semantic-owner and human-procedure risks, not a new universal family.

Future detection candidates include semantic round-trip checks from canonical action identity through visual/accessibility/payload representations and back to owner interpretation.

### 3.9 Fleet/global aggregate versus concrete client payload

Fleet/global aggregate and exported telemetry can disagree with a concrete client/runtime because of build, provider, instrumentation, sampling, offline or residual-cohort differences. Displaying the aggregate next to local actions can create a misleading sense of local certainty.

This reduces to qualified-claim, evidence-currentness, comparability and residual-cohort patterns. Fleet remains **non-authoritative by default** and cannot be treated as the source of local business/control truth merely because the UI can visualize it.

### 3.10 Cross-build UI/telemetry comparability

Two builds can render the same canonical capability name while exposing different generated controls, provider realization and telemetry semantics. Semantic identity alone does not prove presentation or metric comparability.

This remains revision-vector/comparability/compatibility-direction territory. A future viewer may need explicit cohort/qualification semantics; this remains a proof obligation rather than a prescribed UI design.

### 3.11 Graph/fan-out/cardinality pressure

Large nested graphs, lineage overlays, high-cardinality telemetry, generated form dependencies and fan-out actions can exhaust renderer, query, operator-attention or provider resources. The material hazard is not merely slowness but silent truncation/sampling that is then read as complete evidence.

This reduces to existing resource/capacity and evidence-coverage patterns. Boundedness is required as a future proof concern, but no one global bound is inferred in research.

### 3.12 Cumulative privacy/trust leakage

A Graph Explorer can reveal sensitive relationships by composing individually permitted node/edge attributes, tenant boundaries, provider bindings, identities or telemetry. This remains cumulative-privacy and trust-namespace-collapse territory. View-level permission does not establish safe aggregate disclosure.

### 3.13 AI/low-code composition

AI or a human composer can produce a syntactically valid subgraph whose composed path widens authority, targets more subjects than intended, hides required evidence, creates circular/contradictory work, or causes an unsafe fan-out. Path composability remains distinct from semantic/authority composability.

This maps to existing AI/low-code composition, structural graph, authority non-amplification, objective conflict and cross-process families. No new universal pattern is required.

## 4. Typed Semantic Graph / ExecutionEnvelope hypothesis disposition

The prioritized hypothesis **survives this revisit as `HIPÓTESE DE ARQUITETURA / EM PESQUISA` only**.

Evidence **for** the hypothesis:

- typed relations make cross-view lineage and owner/revision/context qualifications representable;
- graph projection is a natural fit for navigable Enterprise→Capability→Contract/Provider exploration;
- separating `CapabilityDefinition` from typed `CapabilityUse/Invocation` preserves reusable semantics while allowing concrete workflow context;
- `ExecutionEnvelope`, `ExecutionState` and immutable `ExecutionJournal` remain useful distinct research concepts for current context, current execution snapshot and historical traversal/evidence.

Evidence **against / trade-offs**:

- a canonical graph can become a semantic god-object if it starts deciding owner-specific truth, authority, policy precedence or provider equivalence;
- Canvas projections can create false certainty through filtering, aggregation, stale revisions or omitted edges;
- recursive/nested graph traversal and lineage overlays create cardinality/operator-comprehension pressure;
- a generic envelope can silently erase semantic type, presence, revision, authority or effect-stage dimensions if treated as an untyped payload bag;
- global/Fleet visualization can tempt promotion of aggregate telemetry into local control truth.

Persistence disposition remains unchanged: PostgreSQL relational tables for graph definitions/revisions/nodes/typed edges plus bounded JSONB for capability-specific configuration remain a plausible baseline. Workflow instances/node executions/edge traversals/journal and business truth remain separate concerns. **No evidence in this revisit requires GraphDB**; GraphDB remains optional/provider/projection-level if later query/scale proof justifies it.
