## Exception tests
1. **Provider-neutral identity:** no counterexample. FOCUS normalizes source shape while retaining provider/resource identity and does not create canonical organizational identity.
2. **Completeness/currentness:** FOCUS 1.4 strengthens dataset completeness, delivery, correction and recency obligations. Missing/late evidence remains `PARTIAL/INCONCLUSIVE`, never implicit zero.
3. **Allocation conservation/residuals:** FOCUS requires summable allocated charges to reconstruct the origin charge; FinOps requires allocation compliance and visibility of unallocated spend. Existing conservation/residual semantics are sufficient.
4. **Internal/on-prem/private-cloud rates:** OpenCost continues to support custom internal pricing without a cloud invoice. Existing `RateBookOrCostModelRevision` remains sufficient.
5. **Historical replay:** FinOps permits multiple allocation strategies/versions; Azure rule edits reprocess views. This corroborates append-and-supersede/replay-under-producing-revisions rather than retroactive semantic mutation.
6. **Budget versus forecast:** FinOps explicitly treats Forecasting and Budgeting as distinct capabilities. No evidence supports forecast mutation implicitly changing budget authority.
7. **Commitment exposure:** FOCUS 1.4 explicitly separates contract commitments, eligibility, used/unused portions and applied economics. No new primitive beyond existing exposure/purchase/eligibility/benefit/unused/internal-allocation separation.
8. **Provider substitution:** FOCUS portability does not erase provider-specific allocation availability, commitment mechanics, latency or native actions. Existing mixed-support requalification remains sufficient.
9. **Showback/chargeback:** Azure allocation changes analytical accountability but not the provider invoice; organizational chargeback remains outside the provider mechanism. Existing boundary is sufficient.
10. **Authority:** no representative supports economic visibility, forecast, budget alert, allocation view or AGWS/AI presentation as purchase, provider-admin, runtime-actuation, statutory-accounting or canonical-domain authority.
