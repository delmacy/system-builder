### Mandatory dedicated research scope — Adaptive Governed Work Surfaces
This concept must be researched explicitly and must not be absorbed into `UI / Generated Experience / Low-code Builder`. The dedicated pass must select 3–8 strong current representatives from composable workspace/low-code families such as Retool, Appsmith, Power Apps/Dynamics, OutSystems, Mendix, ServiceNow UI Builder, Salesforce Lightning/App Builder, SAP Build Work Zone or stronger equivalents discovered at research time.

Required comparison dimensions: component registry; constrained grid/slot/template layout; limited drag/drop; semantic metadata; AI authoring; contextual component/DOM selection; safe data/action binding; mandatory non-removable components; inheritance/policies; Personal/Team/Role/Organization overlays; version/diff/reset/rollback; evidence-governed promotion; accessibility; extensibility; portability; audit/provenance; workflows and external systems.

Required structural model: `Enterprise → Station → Role → Person`, where higher invariants cannot be weakened. `Station` is a first-class boundary for partial suites, inherited/exposed capabilities, delegated administration and a System Builder hierarchically managed by another System Builder. Work-surface automation must distinguish read/action/approval/review/supervised automation and must never exceed Station/Role authority.

Mandatory proof obligations for the future dedicated dossier:
- list/form/grid without creating a new canonical model;
- layout restricted to allowed slots/grid;
- mandatory component cannot be removed;
- personalization is revalidated on Station/Role change;
- AI request requiring domain change is escalated rather than silently materialized;
- action uses provider binding without coupling;
- personal automation respects authority;
- lineage/version/diff/reset/rollback;
- Personal→Team/Role/System promotion is governed by evidence.

All earlier candidates omitted from this compact view remain CANDIDATE pending synthesis; none is revoked.
