# Planning Sequence — From Scope to Development

1. Vision/charter/architecture authority
2. Requirements & scope statement
3. WBS + scope folders
4. WBS Dictionary + Work/Planning Packages
5. Requirements traceability
6. Dependency & interface mapping
7. Risk/quality/resource/communication/change/procurement/cost plans
8. Pre-development readiness review
9. Milestone & increment design
10. Activity/task definition from READY Work Packages
11. Activity sequencing/network diagram
12. Resource and effort estimates
13. Duration/cost ranges
14. Logical/temporal critical path analysis
15. Schedule baseline + release roadmap
16. Sprint loading/capacity balancing
17. Execute incremental spiral
18. Continuous task review + sprint review
19. Every ~3 build sprints: System Integration & Technical Debt Review
20. Milestone acceptance + lessons + replan rolling wave

## Important
WBS termina no work package. Atividades/tasks e cronograma vêm depois. A sprint é uma janela adaptativa de execução sobre uma rede de trabalho já definida; não é fonte de escopo.
