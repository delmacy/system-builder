# Project Planning Plan — System Builder

## Objetivo
Completar a camada de planejamento antes de derivar cronograma, milestones, tasks e sprints. O WBS descreve o **que** será entregue; os planos abaixo tornam esse escopo governável e executável.

## Planning domains
1. Integration & governance
2. Scope & requirements
3. Schedule preparation
4. Cost/finance
5. Quality
6. Resources
7. Communications
8. Risk
9. Procurement/external dependencies
10. Stakeholder engagement
11. Configuration/change management
12. Reviews, lessons learned and transition

## Tailoring para o System Builder
O projeto é software/IA, incremental e majoritariamente executado por agentes. Portanto: estimativas financeiras detalhadas ficam leves até existir consumo real; procurement cobre APIs/modelos/hosting/dependências externas; resource planning cobre humanos, agentes, CI e ambientes; quality e configuration management são fortes desde o início.

## Gate de planejamento
Nenhuma fase temporal deve ser considerada baseline antes de: Scope Baseline; Requirement Traceability; Work Package Catalog; Dependency/Interface Map; Risk Register; Quality Plan; Resource/Agent Plan; Change/Configuration Plan; Review Cadence e Definition of Ready/Done estarem aceitos.
