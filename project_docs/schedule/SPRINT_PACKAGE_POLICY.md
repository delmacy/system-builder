# Sprint Package Policy

It is valid to prepare a small package of future sprint candidates, provided they are marked FORECAST rather than committed.

Recommended initial horizon after task estimation: one active/next sprint committed, roughly two to four candidate sprints forecast, and the remainder represented by increments/milestones/WPs in the DAG.

After every sprint, refresh forecast candidates from actual evidence. After the periodic integration review, regenerate the forecast horizon more deeply.

This balances preparation for cheap coding agents with avoidance of false precision.
