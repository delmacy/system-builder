# Logical Waves

Waves express dependency maturity, not fixed calendar periods.

Wave 0: planning and constitutional gates — contracts, artifact identity, architecture fitness hooks and change/configuration controls.

Wave 1: semantic and identity foundations — ontology/semantic registry, minimal Subject/User/Organization identity, version identity and provenance primitives. Semantic, identity and CI/fitness work can progress as parallel lanes.

Wave 2: process knowledge foundation — Process Mirror, evidence/provenance, knowledge boundary and process versioning.

Wave 3: recipe, analysis and design — Business Recipe, then System Analysis, then System Design. Independent runtime foundations may continue in parallel.

Wave 4: capability/catalog foundation — Capability Registry/SDK, Catalog, contract evolution hooks and dependency/impact identities.

Wave 5: first assembly/validation vertical slice — Assembly plus minimal runtime contracts plus Validation. Objective: first thin deterministic vertical slice.

Wave 6: autonomous artifact/runtime — Compiler and runtime autonomy/certification hooks. Runtime lanes such as Identity/Auth, Actions, Policy, Workflow, Audit, Time and Storage/Documents enter only as required by the selected slice and their own predecessors.

Wave 7: release/deploy — release artifact, environment profile, deployment, rollback and traceability.

Wave 8: observe/support — runtime telemetry and business events feed observation and support/evolution.

Wave 9: improvement/economics — Process Economics, experiment/improvement, reporting/indicators and pattern feedback.

Wave 10 and later: maturity-gated capabilities — simulation, process mining, decision intelligence, optimization, legacy transition, extensions, federation, localization, continuity, factory economics/observatory and broad self-hosting.

## Parallelism rule
A lane may cross a wave boundary when all its own mandatory predecessors are satisfied. Wave numbers never create artificial dependencies.
