# Roadmap Baseline — pre-sprint

## Purpose
Establish dependency-safe delivery architecture without pretending that the complete sprint calendar is known.

## Baseline commitments
- Scope is governed by WBS/Scope Baseline.
- Work Packages own dependency edges.
- Milestones are evidence-based.
- Increments may span multiple sprints.
- Sprint scope is closed at start and replanned through backlog, not kept indefinitely open.
- Long-horizon planning is forecast; near-horizon READY work is commitment.
- Parallelism follows DAG, contracts and integration capacity.
- Review cadence starts at three construction sprints followed by one system integration/technical-debt review, adjustable by risk.

## Next transformation
Detailed NOW Work Packages -> activities/tasks -> machine DAG -> estimates -> critical path -> first milestone increment -> sprint candidates.
