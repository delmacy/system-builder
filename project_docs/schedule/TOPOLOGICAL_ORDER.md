# Topological Ordering

The DAG supports multiple valid execution orders. A topological order is not itself the schedule.

Initial coarse order:
1. constitutional/contracts/fitness hooks;
2. semantic and identity primitives;
3. provenance/process capture/versioning;
4. recipe/analysis/design;
5. capability registry/catalog;
6. assembly/validation plus required runtime foundations;
7. compiler/autonomy;
8. release/deploy;
9. observe/support;
10. improvement/economics;
11. maturity-gated intelligence/ecosystem capabilities.

Within each layer, choose READY nodes by value, risk reduction, criticality, integration opportunity and capacity. Independent nodes may be reordered without changing scope.
