# Planning Artifact Generation Flow

## Stable baseline artifacts
Project scope, WBS, Work Package definitions, WBS Dictionary, requirement traceability, dependency/interface model, milestone graph, quality/risk/change policies and accepted architecture/contracts establish durable authority.

## Rolling-wave artifacts
Near-horizon Work Package planning may refine readiness, risks, estimates, successor forecasts, Sprint goals/exit proofs and detailed TASK specifications. Only the active Sprint is promoted to the commitment horizon; later Sprints remain forecast until predecessor integration and fresh-main revalidation.

## Execution-generated evidence
Authoritative TASK commits, tests, validation reports, exact-head CI, runtime/integration evidence, defects, actual effort where recorded, review findings and package closure evidence are generated by execution/review.

## Repository memory
`docs/current/PROJECT_STATE.md`, `CURRENT_MILESTONE.md` and `NEXT_WORK.md` must be reconciled to integrated truth at the appropriate Sprint/package boundaries. They are current-state authority, not historical logs.

## Feedback
Execution evidence updates risks, DAG/readiness, future decomposition and successor forecasts. It must not erase historical commitments, silently change approved scope, auto-promote forecast work or rewrite architecture/contracts through schedule artifacts.

Therefore detailed Sprint/TASK artifacts are generated close enough to execution to remain reliable, while baseline scope/dependencies remain available for the broader project. Planning, review and closure artifacts must not conceal product implementation.
