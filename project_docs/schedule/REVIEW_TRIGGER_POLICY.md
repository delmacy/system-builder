# Review Trigger Policy

Periodic default: three construction sprints then one system integration/technical-debt review.

Trigger an earlier review when: authoritative contract changes; repeated CI/regression failures; high-severity security issue; migration/schema conflict; critical-path slip beyond tolerance; repeated agent rework; dependency cycle/architecture contradiction; or vertical slice cannot integrate.

A stable low-risk period may justify adjusting cadence through planning governance, but review is never removed solely to increase apparent throughput.
