# Dependency Risk Controls

High fan-in nodes, unstable shared contracts, zero-float foundations and integration bottlenecks are schedule risks.

Controls: stabilize public contract early; add contract tests; reduce fan-in through narrower interfaces; reserve review/integration capacity; create spikes only for unresolved uncertainty; avoid parallel modification of authoritative schemas; keep rollback path for migrations.

Dependency risk is reviewed in periodic system reviews and when critical-path nodes materially slip.
