# Review Cadence — Incremental Spiral

## Continuous gates
Toda task/PR: scope, tests, contracts, architecture constraints e evidence.

## Sprint review
Ao fim de cada sprint: demonstrar incremento integrado, atualizar risks/issues/lessons e verificar carry-over.

## System Integration & Technical Debt Review
Default inicial: **após cada 3 sprints de construção**, inserir uma janela/sprint de revisão sistêmica. A cadência é ajustável por risco e tamanho; não substitui review contínuo.

Checklist: integration ponta a ponta; dependency drift; contract compatibility; architecture fitness; dívida técnica; testes/regressão; security; performance quando relevante; docs/traceability; obsolete code; CI health; agent/rework metrics.

## Milestone review
Validar outcome, acceptance, scope baseline impact, risks, quality, costs e readiness do próximo horizonte.

## Regra
A sprint de revisão pode conter correções, mas não deve virar depósito de defeitos que deveriam bloquear merges normais.
